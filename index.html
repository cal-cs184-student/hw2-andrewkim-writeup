Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau’s algorithm is a process we use to evaluate a given point at a timestep t (ranging from 0.0 to 1.0) along a Bezier curve defined by a set of control points. At a high level, the algorithm linearly interpolates neighboring pairs of control points, connects these new intermediate points, and recursively repeats the process until a single point is reached. This final point is the location on the Bezier curve. At each subdivision level, the number of points we have reduces by one which enables us to collapse to a single point. Let’s walk through this algorithm using an example.

Our variable t is a measurement of time ranging from 0.0 to 1.0. In our example, let’s say we want to find where to place a pixel on our screen at timestep t = 0.5, which is halfway along a Bezier curve defined by six control points:

Our control points are given in white, with the Bezier curve in green. Given the placement of our points, we drew lines connecting them, giving us five new lines as seen above. Now using our parameter t, we can place a dot 50% of the way along each of these lines by linearly interpolating the corresponding control points using our formula p’i = lerp(pi, p(i+1), t) = (1 - t)*pi + t*p(i+1), then connecting them. These changes are seen in blue:

For this assignment, we stop our function evaluateStep() at this point after evaluating one level of subdivision. However, the full algorithm continues to run subsequent levels of subdivision until it reaches a single point, the location on the Bezier curve. To implement evaluateStep() in order to evaluate Bezier curves, I first created an std::vector named intermediates which will hold the current intermediate control points for this subdivision level. I then iterate through the points in the given points vector, linearly interpolating them based on t to create new intermediate points, which are then added to intermediates. Finally, I return intermediates.

Let’s see how the full algorithm would unfold if we were to continue: we repeat the process recursively on our five new dots, linearly interpolating them by placing four more dots 50% of the way along the lines and connecting three more lines:

Continuing with two more subdivision levels, we end with a single dot (in red), which is the location on the Bezier curve at timestep t.

To take it a step further, in order to draw the entire Bezier curve on the screen, we run de Casteljau’s algorithm for all timesteps from 0.0 to 1.0, repeating the process until the curve is fully traced out. However, in this example we just ran the algorithm once with our parameter t = 0.5.

Part 2: Bezier surfaces with separable 1D de Casteljau

De Casteljau’s algorithm seamlessly extends to Bezier surfaces by going from 1D curves in 2D space to 2D surfaces in 3D space. We are given a 2D, n x n list of 3D control points and two parameters, u and v (both ranging from 0.0 to 1.0), since we are now operating in 3D space. We run de Casteljau’s algorithm the same way we did in part 1, this time on each row using u and treating these points as a 1D curve until we reach a single point for each row (n total points for the n rows). In essence, we can then treat these n points as their own 1D bezier curve along the columns of our 2D list and then run the algorithm one last time on these points, this time using our parameter v. We end up with a final single point that lies on our Bezier surface at the parameters u and v.

In order to evaluate Bezier surfaces, I implemented the algorithm by modifying three functions: evaluateStep(), evaluate1D(), and evaluate().

In evaluateStep(), I implemented the same logic from part 1, this time using 3D points instead of 2D ones. This function will find the intermediate control points at the next subdivision level of our points. I first create a vector intermediates which will store these points. I then iterate through the vector points (up to points.size() - 1 to avoid out of bounds errors), linearly interpolating neighboring 3D control points before adding them to intermediates. I end by returning intermediates.

evaluate1D() will be responsible for evaluating the final, single point that lies on the Bezier curve at the parameter t, which I implemented recursively. I start by checking the base case of whether or not our list points has just one element. If it does, I return that point, which is the point that lies on the curve. Otherwise, I call evaluateStep() on points and t, finding the intermediate points at the next subdivision level, ending by returning a recursive call to evaluate1D() on these intermediate points and t.

Our last function evaluate() is responsible for outputting the final point that lies on our Bezier surface. To implement it, I start by creating a new vector of 3D points, finalPoints, which stores our n evaluated points at each of the n rows of controlPoints. To find these points, I call evaluate1D() (as implemented above) on each row of controlPoints using our parameter u, adding the evaluated points to finalPoints. Now that we have a new set of control points, we can treat them as their own 1D Bezier curve and call evaluate1D() one more time on them using v, returning this last evaluated point. This final point is our point that lies on the Bezier surface at parameters u and v.

Part 3: Area-weighted vertex normals

To implement the area-weighted vertex normals, I modified the function normal() by first creating a running sum of all area-weighted normals, sumOfNormals. I then grab the starting half-edge of our vertex and make a copy to use in the loop condition, both using HalfedgeCIter as described in the spec. In my loop, I start by checking if our face is valid and not on a boundary, since some triangles are along the borders of our object. I then compute the cross product by getting our three vertex positions for the current triangle face using the half-edge data structure and compute two edge vectors. By then calling cross() on these edge vectors, we get a face normal whose magnitude is proportional to twice the triangle’s area. I end by adding our cross product to sumOfNormals. In my implementation, I use a do-while loop with the condition: while our current half-edge isn’t the same as our starting half-edge. This allows us to run one iteration first before we “increment” by changing our current half-edge to the next half-edge around the vertex and prevent premature exiting on the first half-edge. To end the function, I normalize and return the vector sumOfNormals with a call to the helper function unit().

Part 4: Edge flip

To implement the edge flip operation, I modified the function flipEdge(). I first check if our given edge is a boundary and return if it is, since we can’t flip an edge that is one. I then break the problem down into two parts: the first finds all of the elements in the mesh and the second reassigns pointers in the modified mesh after flipping the edge, regardless of whether they are unchanged or not to prevent errors as explained in the spec. I also implemented this function without adding or deleting any mesh elements since edge flips don’t do so.

To start the first part, I find the two inner half-edges as well as the four outer half-edges by creating HalfedgeIter iterators and assigning them appropriately using the HalfEdgeMesh class functions halfedge(), twin(), and next(). Then, I find the four vertices and edges as well as the two faces, again using these built in functions to assign them all running counterclockwise.

In the second part, I start by calling setNeighbors() on each of the six half-edges, reassigning the pointers of the top triangle and then the bottom one to their new elements after flipping. An important thing to note here is that we started with a left and right triangle since our initial edge ran vertically, but now it runs horizontally after flipping clockwise, so we have a top and bottom triangle. The geometric properties then change where the top right edge now belongs to the “left” triangle (the new top one) and the bottom left edge belongs to the “right” triangle (the new bottom one). I continue by updating the vertices, edges, and faces to point at their new half-edges before returning e0 to end the function.

Part 6: Loop subdivision for mesh upsampling

To implement loop subdivision I modified the function upsample() by splitting it into the five parts given to us in the spec and starter code.

To start, in the first part I began by iterating through each vertex one by one and setting their isNew> tag to false> since they are not new vertices. I then create two counter variables to keep track of the number of neighbors each vertex has as well as their neighbors’ combined position vectors. I then find the neighbors using the half-edge data structure, keeping track of the starting point to use as our nested loop condition. In the inner loop, I get the current neighbor’s position and add it to our running sum, increment the number of neighbors, then move onto the next half-edge and vertex, ending the do-while loop by checking if we returned back to our starting point. Finally, I get the correct smoothing factor as well as update the position of our current vertex.

As for the second part, this time I loop through every edge in the mesh and set their isNew> tags to false since they aren’t new. Then, after getting the first and second endpoint positions, as well as the two outer vertex positions of the triangles sharing this edge, I apply the new vertex position from the spec to get the position of the new vertex and save it in the edge’s newPosition.

In the third part, I start by creating a list to store pointers to our edges and fill it up in order to keep track of which edges were originally there at the beginning. I then iterate through these original edges, get their smooth midpoint coordinates we saved, and store them before splitting. I then call splitEdge() as previously implemented, set the new vertex’s isNew> flag to true>, and set its newPosition to the coordinate we just stored.

For the fourth part, I iterate through all the edges in the mesh, new or old, and check if they are new. If one is, I grab both of its endpoints and call flipEdge() on it if they connect one old and one new vertex. This is to ensure our triangles don’t end up looking uneven.

Finally, in part 5 I once again iterate through every vertex in the mesh and change the current vertex’s position to its newPosition to change the shape of the mesh. I end by setting the isNew> flag to false for the next round of loop subdivision, since they will no longer be new at that function call.
